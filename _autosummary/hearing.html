hearing¶

hearing — pluggable meeting transcription & context-aware AI agents.

A small, composable toolkit for capturing, transcribing, and reasoning over meeting audio. Four swappable concerns compose into one pipeline by dependency injection: audio capture (mic + system audio on separate channels) -> STT engine facade (local or cloud) -> optional diarization / speaker-id (the mic-vs-system channel split gives “me vs them” for free) -> an agent layer that consumes the transcript (batch or live).

Progressive disclosure — the one-liner just works:

from hearing import transcribe
transcript = transcribe("meeting.wav")
print(transcript.formatted())

…while engine selection, diarization, agents, channel routing, and the live loop are all optional keyword-only arguments.

The architecture and the per-concern guidance live in the project’s agent skills (.claude/skills/hearing*); start with the hearing skill.

class hearing.TranscriptSegment(text, span, channel=Channel.MIXED, speaker=None, confidence=None, words=(), meta=dict())[source]¶

Bases: object

The data spine — a standoff interval annotation over the audio.

Required fields are text and span. Everything else is optional metadata that a concern enriches: STT sets text/span/ confidence; capture sets channel; diarization sets speaker. Segments are frozen — enrich by copying (with_speaker/with_channel), never mutate.

>>> seg = TranscriptSegment("hello", TimeSpan(0, 500))
>>> seg.with_speaker(ME).speaker
'me'
>>> seg.text
'hello'

async hearing.live_transcribe(*, source, engine=None, diarizer=None, agent=None, audio_queue_max=50, segment_queue_max=100, on_insight=None)[source]¶

Stream FINALIZED segments as a meeting unfolds (the live path).

Same components as transcribe() — only the source (a streaming CaptureSource instead of a file) and the trigger cadence (VAD utterance turn-ends instead of run-once) change. The STTEngine and AgentConsumer interfaces are unchanged.

Each channel is demuxed onto its own bounded queue and driven through engine.stream_transcribe as an independent async task, so a slow agent never stalls capture (backpressure) and the channel “me vs them” label rides every segment. Diarization defaults to the free channel trick; the agent’s on_segment is fired fire-and-forget; whatever it returns goes to on_insight(insight, segment) (sync or async), and is dropped without one. Yields segments as utterances finalize.

See the hearing-live-pipeline skill.

hearing.transcribe(source, *, engine=None, diarizer=None, agent=None, language=None, split=True, mic_channels=(0,), system_channels=(1,), record=None, record_audio=False)[source]¶

Transcribe an audio source to a Transcript.

The one-liner transcribe("meeting.wav") works with all defaults: the default local engine (faster-whisper), automatic channel splitting when the file is multi-channel, and the free “me vs them” channel-trick diarizer.

Parameters:

  • source (str | Path | CaptureSource) – a file path or any CaptureSource.

  • engine (Optional[STTEngine]) – STT engine (default: faster-whisper). Inject any STTEngine.

  • diarizer (Optional[Diarizer]) – speaker labeller. None -> the channel trick is applied automatically when channel info is present (mic=”me”, system=”them”). Inject a PyannoteDiarizer to separate individual remote speakers.

  • agent (Optional[AgentConsumer]) – optional AgentConsumer run over the finished transcript (batch). Its output is stored under transcript.meta['insight'].

  • language (Optional[str]) – force a language code (e.g. “en”); None = auto-detect.

  • split (bool) – split mic/system channels when the source is multi-channel.

  • system_channels (Sequence[int]) – column indices for the channel split.

  • record – optional MutableMapping store (e.g. a dol store) or MeetingStore to persist the transcript JSON (with the agent’s insight) under key "<source>.transcript.json", i.e. meeting id <source file name>; hearing.context.meeting_retriever reads those back as the next meeting’s context.

  • record_audio (bool) – also keep the source file’s audio bytes, in record’s separate recordings store (a MeetingStore made with recordings=), read back with record.recording(meeting_id).

Return type:

Transcript

Returns:

A Transcript (iterable/len-able, so it stands in for a sequence of segments). Segments carry text, span, channel, and speaker.
